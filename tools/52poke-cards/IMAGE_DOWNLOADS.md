# 卡牌图片下载：已跑通的路径与限制

## 官网“卡面＋说明”组合图的本地裁取

`public_collage_cards.py` 仅对已下载且校验过的官网缓存做候选裁取。
目前只支持明确的左侧完整卡面、右侧说明布局：保留全高和少量边缘，不缩放、不重绘文字。
裁取结果保存母图 SHA-256、坐标、来源页和输出哈希，仍须独立读取完整卡牌身份后才能关联。

这类结果标注为“官网配图裁取，非原件”，不会替换已有原图。普通原图优先于裁取图；
处理流程不会读取受限研究目录。源站下载数与本地产生的裁取数分开统计，
不能把后处理结果说成又下载了新的原图。

首批 10 个裁取候选中有 1 个通过核对，其余未强行接受；当前仍不代表全量卡图已取得。

## 2026-10-19 补充：公开缓存识别纠错与续传保护

`review_card_details.py` 只处理完整卡号、卡名和来源能匹配一个待下载目标的公开官方缓存。
给识别服务的输入为同一张图片的全图、放大标题和放大页脚，不提供目标答案提示；
仍要求两次独立读取在语言、置信度、完整标识和 HP 上一致。旧结果保存在 `ocr_history`。
受限研究缓存路径不允许进入这条识别流程。

对于被误放进系列代码或卡号字段的独立监管码字母，仅当另一独立读取完整确认余下字段时才拆分，
保留原始读数和拆分记录；不删除连写的字符、不丢弃卡号的数字前缀，也不截掉含糊字符来凑匹配。
低置信度或不一致结果仍保留待审。

重新运行旧的 `download_images.py prepare` 时，同一归档中的已校验跨来源图片和补充引用会保留，
不会被仅支持亚洲卡牌站的旧解析器清空；不同归档必须使用新缓存或明确迁移。
已确认逐字节一致的原图不会被普通识别结果降级替换，文件级内容哈希证据也不会丢失。

剩余目标清单由 `report_remaining_images.py` 离线生成，保存在
`sources/current-access/remaining-simplified-targets.json`，包含原始引用、已缓存的最新文件元数据、
来源限制与本地研究替代图标记，不把研究图计入公开图库或 Wiki 原件完成数。

另有 7,085 条简体印刷记录没有明确图片字段，仍需补来源，不计入这 1,775 条。
归档记录中找到 133 个明确引用的大陆官方来源页。

- `official-candidates/wiki-card-references.jsonl`：完整的上述卡图引用与印刷身份。
- `official-candidates/download-list.jsonl`：来源页实际公布的候选图片 URL、状态和来源。
  来源页仍在扩充时，此清单会增加；候选也可能是宣传图，不等于全部都是卡牌。
- `official-candidates/candidates.sqlite`：持久化任务、文件校验记录、处理结果、错误和耗时。
- `sources/current-access/progress-latest.json`：分别统计落盘图片资源、下载队列、匹配卡图和各进程状态。

三个独立进程通过 SQLite WAL 队列协作：

1. `plan`：先整理本地卡图引用，再读取明确的官方来源页，把实际公布的图片 URL 加入队列。
2. `download`：唯一的图片下载进程，串行取队列；落盘立即取下一条，**不读取密钥、不调用 OCR、不等待识别**。
3. `process`：只读取完整落盘的本地图片，使用独立的模型工作线程。模型慢、失败或暂停都不堵塞下载。

```bash
cd .
# 先用已缓存来源页立即准备第一批 URL，不重复请求。
.venv/bin/python image_pipeline.py plan --cached-only
# 三个终端独立运行；先启动清单准备，再启动消费者。
.venv/bin/python image_pipeline.py plan
.venv/bin/python image_pipeline.py download --follow
.venv/bin/python image_pipeline.py process --follow --ocr-workers 2
```

下载完整有限清单后退出，不持续猜测新 URL。各命令有独立文件锁，可以同时运行，
但**不要再并行启动旧的 collect_official_candidates.py**。
已落盘文件、已有识别结果和失败记录可恢复，不因为程序重启而全部重下。

后处理只做完整性/哈希校验、准确印刷身份关联、来源及语言记录和前端适配；
不会修改原图中文字。已公开编号映射的 151 活动图可以直接确定身份，不需要逐张 OCR。
只有身份不明确的候选才使用识别，首次连必要编号都识别不出的图片不再浪费第二次调用。
目前模型识别关联仍要求双读一致、相同来源页、系列、编号和卡名，不自动降低门槛。
置信度来自模型而非人工审校；相关记录明确标记 `human_reviewed: false`。

大陆官方图片源目前串行、上限 1,000,000 字节/秒，保持请求间隔并遵守该来源的 robots。
这个限速**不适用于 Wiki**，也没有放宽 Wiki 的请求规则。Wiki 直连 CDN 403 未被绕过，
原站最新取得的 `Crawl-delay: 500` 按秒处理，不误读为 500 毫秒。
官方来源的 401/403/429 停止相应请求，不换身份或 URL 凭据；模型的限流只暂停处理。

96 项离线测试通过，新增测试包含：OCR 阻塞时下载照常完成、下载器不接触密钥、

## 请求限制与失败处理

- 单队列文件锁，禁止并发运行；单线程、逐张下载。
- 固定、可识别的应用 User-Agent，无浏览器 Cookie。
- 平均应用读取速率 250 KB/s，请求结束后至少等待 0.75 秒；尊重来源 robots 的更长间隔。
- 可能超过 500 次请求的批次仅允许在 Asia/Hong_Kong 的 02:00–08:00 开始及继续。
- 401/403 立即暂停并记录访问限制，不自动换身份或继续试其他头部。
- 429 遵守 Retry-After；404/410 标记 `missing_source`，不循环重试。
- 普通失败最多自动进入三次有间隔的尝试；后续需要人工检查。
- 非图片响应、截断文件、非法跳转、模糊多图来源不会记作成功。
- 缓存文件损坏时报告错误，不静默反复下载。
