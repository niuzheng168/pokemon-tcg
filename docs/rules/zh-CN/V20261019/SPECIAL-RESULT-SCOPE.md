## 2. 三个文例：确定条件，不混淆单位或执行身份

| 文例 | 可以确定的条件和结果 | 不能替换成的条件 |
| --- | --- | --- |
| 未知图腾 V（CS6.5）「胜利象征」，p75 | 实际使用该招式时，**自己的剩余奖赏恰为1张**，特殊结果为自己胜利 | 不是已经拿过1张；不是剩余至少1张；不要求再拿走最后1张 |
| 未知图腾（CSM1a）特性「手牌」，p75–76 | 该宝可梦在自己的战斗场；在自己的回合宣告使用，**每回合可用1次**；自己的实际手牌 **≥35张** 时自己胜利 | 不是备战区也能用；不是只在场上有它且手牌达35便自动获胜；不是全局只许一次或所有同名实例共用一次 |
| 呆壳兽（CSM2a）「华丽赌注」，p76 | **本次原有的3次硬币**决定正面数×100基础伤害；同组结果全反面时自己败北 | 不是另外重掷3次；不是实际伤害为0便败北；不是招式失败检查、反面即停止或缺失回执算全反面 |

这三项是 E38 明文；使用流程／次数仍受 I.A、E12 及实际获审卡文约束。
普通未知图腾的35张条件失败、又没有其他可执行内容时，不能绕过 I.A-02 p8
的主动特性无变化使用门槛。手牌达到35张不创造另一个随时可插入的“宣告胜利”窗口。

**“胜败宣告”应只是软件对结果指令的命名。** E38 没有另列一个玩家可以延后、
抢先或拒绝的胜利／败北宣告动作。玩家先合法使用对应招式／特性，
其说明文的条件满足才产生特殊结果；不在选招菜单、观察手牌数量或记录“已使用”
事件时提前结束。对于包含复制／授予的情况，实际使用者与原卡持有者不能混同；
本子集不凭 E37 的“拥有”说明自动批准那些组合。

### 同一3币的最小 oracle

| 原组正面数 | 3币排列数量 | 文本基础伤害 | E38 己方败北 |
| --- | --- | --- | --- |
| 0 | 1 | 0 | 是 |
| 1 | 3 | 100 | 否 |
| 2 | 3 | 200 | 否 |
| 3 | 1 | 300 | 否 |

回执必须是本次实际执行、对应 coin key 的 `fixed(3)`，有3个实际结果，
且 heads／tails／flips 与结果一致。伤害和败北条件读取同一个回执，
恢复不重掷、不借用上一招或父／子复制执行的回执。伤害被减至0／被防止，
也不能把“有正面”的原组改判成全反面。
I.A-01 p7 的零基础伤害会结束该次伤害计算，但不是取消 p6 步骤5的其余效果；
因此全反面时伤害为0，不会因此跳过 E38 的败北内容。

## 3. 执行动作的位置与终止时刻：能推导到哪里

### 3.1 已知顺序

1. **招式宣告不是招式内容已经执行。** I.A-01 p5–6 还需处理招式使用失败、
   混乱等步骤；不能在进入这些检查之前仅因奖赏为1就发特殊胜利。
2. **正常招式流程先伤害、再除伤害外的内容。** p6 步骤4→5→6受伤反应→7昏厥。
   没有专门指示时，步骤5按说明文顺序执行；据此可将 E38 的非伤害结果作为
   真实效果程序中的指令，而不是回合末全局扫描出的额外胜负条件。
   “使用这个招式时”不等于原件另给了一个可抢在使用成功检查前的时点。
3. **特性在执行说明文时处理条件／结果。** 普通未知图腾按 I.A-02 p8 的
   宣告／使用条件／执行说明文流程，不因检查／对手回合手牌恰到35便自动发动。
4. **普通昏厥与普通胜负有明文等待边界。** I.D p14 将效果相关处理末尾列为
   昏厥确认点；其步骤包含反应、弃置、奖赏。I.E p15 要求在相关处理期间
   达成其列举的普通败北条件时，把相关处理做完再判定。

**I.E 等待规则的原文限定为“以下任一条件”；E38 定义又明确使用 I.E 以外的方式
决出胜败。** 所以“普通胜负必须等待”是已知规则，但不能省掉适用范围，
直接证明“特殊胜败也必须等全部 KO／奖赏结束”。

### 3.2 四种看似通用的推导，缺少的前提各是什么

| 尝试 | 实际不足 |
| --- | --- |
| I.E 要等待，所以 E38 也等到相同位置 | 缺少 E38 被纳入 I.E 所列条件／等待范围的前提；E38 首项反而区分两类判定方式 |
| II.A 卡文优先，所以 E38 一定立即清空余文、反应、KO、奖赏 | E38 明确改写胜败方式，但没有明说对整个处理链的打断规则；“立即丢弃剩余任务”不是原文指令 |
| I.D 要处理昏厥，所以特殊结果前一定先做 KO／拿奖赏 | I.D 规定何时确认和怎样处理昏厥，没有单列它与 E38 决胜的优先序 |
| E19 要执行 then，所以特殊胜利之后一定还能执行 then | E19 描述正常前后文依赖，不单独规定已决出特殊胜败后游戏还继续到哪里；反过来，也不能用结果条件成立冒充所有前文已执行 |

因此不能把“原文未说立即”当成“已证明必须等待”，也不能把“算作胜利”扩写成
“官方已逐项规定跳过所有后续工作”。**未知集中于存在真实竞争处理的终止／优先序，
不是三个条件本身，也不是所有 E38 程序都不可实现。**

## 4. 可立即收敛的第一子集

### A. 条件查询／到达事件

可以实现三个严格 typed 条件、原执行回执复用及“条件已到达”的事实记录，
不消耗 RNG、不拿奖赏、不修改指示物／手牌来凑条件。条件不成立时不产生特殊结果，
原本可执行的说明文和普通 KO／胜负流程照常；不因操作类型叫 E38 就一律未决。

这层不需要先解决“出现竞争时谁先结束”。它也不能冒充已经提交了最终胜败。
缺失／伪造执行回执、未获审卡文绑定或非法来源属于协议拒绝，不应默认为条件不成立。

### B. 无竞争、相关处理已到确定收尾的实际终局

**可安全实现的宿主子集约束：** 合法、稳定的局面中，当前获审效果的特殊结果条件
成立；没有能影响胜败的未执行余文、相关反应、待处理 KO／奖赏或其他竞争结果，
只剩无游戏作用的收尾。此时按该文例给出的自己胜／败提交结果。

推导前提逐项为：①E38 已明定此条件的胜者；②没有另一个结果与它竞争；
③没有剩余相关作用可改变条件或结果；④此后不需要通过新的玩家行动才能成立。
于是“在该指令处结束”和“在本次相关处理的无作用收尾后结束”得到同一个胜者，
无需先裁定一般打断优先序。**这是限制软件接收范围，不是假称原件给了新时序规则。**

可先接普通未知图腾的独立主动特性：它的文例只判断在战斗场／自己回合／使用次数
和手牌数，成功结果本身不造成新伤害、KO 或奖赏移动。宿主仍需确认没有实际
关联反应／未决工作，不能仅凭卡名跳过检查。这至少能交付一种真正改变对局结果
的 E38 语义，而非只保存查询结果。

招式也可在同样约束下接入，但完整卡面、其他绑定、使用成功及相关效果必须另审，
不能因指南文例只摘了结果文字就断言整张未知图腾 V 没有其他内容。
呆壳兽全反面的隔离分支基础伤害为0，不能凭本次这段伤害产生 KO／奖赏；
在确无其他相关作用时也可归入本子集。普通后续回合不能被任意延长出来，
作为拖延已成立特殊结果的理由。

### C. 确有竞争的组合：只保留具体未决

| 组合 | 能确定的结论 |
| --- | --- |
| E38 条件不成立 | 没有该特殊结果；继续已获审的其他流程，不属于特殊／普通冲突 |
| 特殊结果与普通结果都指向同一胜者 | 胜者一致可确定；若仍有相关收尾，其执行／截断顺序须另审，不因此把整局胜者都标未知 |
| 特殊自己胜利，同时普通条件导出自己败北 | 当前来源没有二者优先表；`needsRuling`，不能把特殊胜利当成普通表中“多一个条件”计数 |
| 特殊自己败北，同时普通条件导出自己胜利 | 同样 `needsRuling`，不能默认“先写入 result 的任务获胜”或套普通平局表 |
| 真有余文／受伤或昏厥反应／奖赏作用能改变竞争结果 | 中断与继续的区别尚无该组合的直接依据；记录具体未决，不泛化至 B 子集 |

**避免伪反例：** 不能让呆壳兽同一原组同时是3正面以打出300、又是3反面以特殊败北。
这违反其共用3币的明文，不是需要裁定的同时胜负。普通未知图腾在已经合法结束的
对局再主动发动，也不是普通／特殊真实冲突。只有满足使用流程且确有相关作用的
有效组合才进入上述优先序未决。

## 5. 可实现 typed 指令／事件的最小建议（尚未编写）

软件协议可先用三个不可自由改写条件的 profile，而不是接受任意玩家报“获胜”：

```js
{ op: 'specialResult', profile: 'CN.E38.remainingPrizeOne', outcome: 'win' }
{ op: 'specialResult', profile: 'CN.E38.activeHand35', outcome: 'win' }
{ op: 'specialResult', profile: 'CN.E38.originalThreeTails',
  outcome: 'loss', rollKey: 'reviewed-original-roll' }
```

建议 oneOf 严格绑定 profile／结果／所需来源类型：前后两个为招式，中间为主动特性；
全部结果对象都是**实际使用者自己**。不接受外部指定 winner、任意阈值、
任意时点、缺省掷币组或可编辑的终止策略；卡文审批和来源固定仍是独立门禁。

满足条件时可记录：

```js
{ kind: 'special-result-reached', executionId, instructionIndex,
  source, player, profile, outcome, facts, sourceOfTruth }
```

这里 facts 只保留该 profile 的实际条件事实及需要的原 coin 回执引用；
私有事实不因记录事件就自动公开，不能在公共日志泄露手牌内容。
`sourceOfTruth` 至少指向固定 E38 p75–76，使用／执行边界另引用相应 I.A、I.D／E。
事件不是一个玩家身上的 lasting 效果：E38 p76 明文说它不属于施加于玩家的效果，
不能通过玩家效果保护或可编辑持续 ledger 将其自动取消／授予。
这个事实也不替代招式／特性的使用条件和终止优先序。

宿主只在第4节 B 的已验证子集另行提交最终结果；其他竞争不能悄悄回退普通
`afterKO` 或给客户端一个 `immediate=true` 自选。若要支持未决组合，须补来源
并明确准入／挂起策略，不能执行半条后把未知误作默认败北。
这些字段是提案，不是官方 JSON 规范，也不意味着当前 GameState／命令／schema 已支持。

## 6. 独立验收建议与本轮交还

- 奖赏剩余0／1／2：只有1命中；正常60张局面“已拿1、剩余5”不命中，
  “已拿5、剩余1”命中；查询不调用“已经获得奖赏数”来替代剩余数。
- 普通未知图腾：手牌34／35／36，战斗／备战、己／对手回合及已用／未用交叉；
  达35不自动发动，合法使用成功后才有特殊结果。
- 枚举原3币8种排列；恢复／重放 RNG 不变；缺币、错误 coin key、其他 execution、
  把0实际伤害当全反面、对败北再掷币均拒绝。
- 无竞争子集分别提交正确胜／败；假条件不阻塞普通流程；同胜者不误标胜者未知；
  相反结果或真实未结工作只验证安全拒绝／未决，不伪造其优先序 oracle。
- 到达事件、最终提交事件与原获审绑定／实际执行身份锚定；不从任意历史
  “曾经满足条件”记录重放出新的胜利，不因 E38 不是玩家效果而略过使用流程。
