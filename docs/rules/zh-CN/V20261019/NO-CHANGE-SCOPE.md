**不能删除 EX。** 本轮核读到的不只是“受保护仍能选”，还有训练家卡
本身可以使用的明文。它是 E29 指定来源／区域／卡类的规则，不能反过来扩成
所有保护都允许空放；同样，U 也不能覆盖该明文，生成“所有保护都禁止空放”的
一刀切。C07／C17 讨论招式保护，不足以证明一个训练家或特性的保护前提。
四类 native 的一般门槛应与已核验的 E29 适用／专门许可分开，不能仅按 op 名判断。

## 3. 费用、付款后资格与存在性

- **费用不是后续效果。** E30 p69 将弃手牌列为使用条件；p70 以再构筑的
  空牌库 FAQ 说明，即使能弃两张手牌，也不能只为弃牌而使用。
  U 的使用次数消耗、普通物品／支援者的展示和用后弃置也不能救活空效果。
  但卡文若把弃牌写作说明文本身的效果，就不能误标为费用后全部忽略。
- **按真实付款后的局面判断后续。** 轰鸣引擎的成本是一张能量，后续是抽至六张
  （E30 p69）。在能合法付款且牌库非空时，原六张手牌付一张后仍可抽；
  原七张付一张后已有六张则不再有抽牌变化。这是 U＋COST 的通则推导，
  不是原件另列了这两个手牌数量的 FAQ。不能只查看付款前手牌数。
- **存在可行付款，不是任选一份付款充当证明。** 对付款和后续资格均已可判定的
  子集，软件资格应表达“存在一份完整合法付款，付款后满足使用规则”；实际
  回答还必须核验玩家选中的那一份，不能因另一份付款可行就接受本份不可行付款。
  这是使用条件的工程化存在量词，不冒称原件逐字规定了付款搜索算法。
- **全部付得起不等于所有付款都留下效果。** 不能用付款前 canUse 与某个可支付
  证明各自为真，就当它们对应同一份合法局面；也不应要求每份可选付款都能用。
  若费用会改变保护／候选、产生其他反应，且具体依赖还没有证据，该付款分支
  保持 `needsRuling`；另有已知可行付款或独立效果证明可用时，不以未知分支否定
  整次使用，更不是让“付款造成了变化”替代后续资格。
- **先验证，后真实支付。** 只读投影付款后局面是建议的软件安全做法，
  不是新官方时间窗口；本次不批准扩大费用种类，也不裁定费用触发的其他效果
  是否能挽救原本不能执行的后续。

## 4. 独立 binding、then 与事件选择权

**独立 binding 的 OR 只适合真实独立效果。** 治疗部分不可执行而另有独立抽牌，
与“先治疗。然后抽牌”不是同一关系；不能拆成两个 binding 后对它们做无条件 OR，
也不能把两个独立部分误设为必须都成功。THEN 的伙星 FAQ 说明后段没有对象，
前段仍可执行；芽米 FAQ 说明回复者没有能量仍可回复。玛俐 FAQ 则说明，
不能把前段完全无法执行时的抽牌后段拿来证明可用。EX 的古兹马同时提醒：
**宣告许可与后段是否执行，是不同问题**，不能从“允许使用”猜 then 已成功。

**`trigger.optional` 不是官方分类。** 应先有获审说明文证明这是：
①事件窗口内可选择使用的特性，②整个效果“若希望”的选择，
还是③必须生效的自动效果。TR 的进化／上备战／附能“可使用1次”是限定机会；
E10 p58 的“若希望”决定是否执行其后内容；U p9 的自动特性不可任意关闭。
软件 optional=true 不自动豁免无变化门槛，optional=false 也不自动证明是强制自动；
有明确使用条件的条文不能被这一个布尔值擦掉。本次不裁定未审卡文的触发类型，
也不将所有触发效果都导入主动 canUse。

## 5. 重复特殊状态：不能靠字段相等裁定

| 情形 | 已读证据能证明什么 | 无变化资格结论 |
| --- | --- | --- |
| 特殊中毒后再普通中毒，或普通中毒后再特殊中毒 | E16 p61 明确新状态覆盖旧状态；毒指示物数量不同不能只比较“已经中毒”布尔值 | 可证明参数会改变；仍需检查来源、卡文和完整使用条件 |
| 已中毒，再施加同强度／同参数中毒 | 本次核读未见同参数重复施加能否主动宣告、是否发生规则意义新状态的直接实例 | **needsRuling**，不按 `old.poison === next.poison` 判禁止，也不凭覆盖不同强度的文例宣称一概允许 |
| 已睡眠再睡眠、已混乱再混乱 | 本次核读没有同状态重复主动施加的明确实例 | **needsRuling**，`rotation` 字符串相同不是官方无变化证明 |
| 已麻痹再麻痹 | 检查时点与状态自身信息必须区分；当前代码可能保存恢复回合，但代码赋值不是裁定 | **needsRuling**，既不能只比 rotation，也不能凭软件刷新时限就证明可用 |
| 取得效果保护时已经有特殊状态 | C17 p39 FAQ2 明确既有中毒不因此消失 | 不是重复施加同状态的许可／禁令，也不解决上面三个未决 |

II.C-02 p26 是**放回手牌／牌库**，不是“重复特殊状态”的规则；
其清除附加效果的说明、C03–05 互换清状态、I.F p16 的检查流程，
都不能冒充同状态重复施加的专门依据。
这里“未见”限于本次实际核读范围，不声称全站没有其他官方简中裁定。
未知不能默认为无变化；也不能靠日志新增、source 指针变动或两个状态 JSON
不相同，反过来宣称已经发生足以使用的官方效果变化。

## 6. 本轮代码边界与交还

只读对照过 [game.js] 的 `activationInfo / activationUsable /
activationEffectsUsable / payActivation`、`trigger-execute / entry-use`，
[handlers.js] 的 native `canUse / canUseWithCosts`，
以及 [conditions.js] 的 `applyCondition`。这些是后续接线接点，不是规则来源，
本审查不追认其当前行为，也不以并行 worktree 的临时状态断言最终缺陷。

**父线后续软件表示／源审查边界（反馈记录，非本文件实现验收）：**

- `protection.useRule` 被设为必填的 `ordinary | CN.E29`，**无默认值**，这是项目区分普通遮罩
  与 E29 使用许可的 **JSON 协议，不是官方要求的属性**。分类必须绑定获审简中
  来源；不能从相同的 origin 覆盖集合自行推得 E29，也不能凭填写字段选择适用规则。
  `ordinary` 不批准任何未经来源审核的普通 hand shield 实卡，`CN.E29` 也不自授许可。
- 父线当前 `CN.E29` 严格限定被阻挡的效果为 effects 通道、trainer 类别、
  hand origin、Item／Supporter。**受保护 subject 只支持场上 Pokémon**，
  盾的生产者可以是 Stadium；不能混淆盾的来源与受保护主体。
  Stadium 来源加 `self` 须以 `unsupported-protection-subject` 拒绝，
  原 E29 雷霆山所涉及的场地卡本体范围仍缺，不能宣称已有场地卡 subject。
- timed AST／ongoing 禁止承载 `CN.E29`；此许可只能来自获审的在场持续盾，
  不能让可编辑的持续效果 ledger 自行签发。以上是本轮限定软件表示，
  不是官方 JSON 要求，也不是所有 E29 形态已经支持的声明。
- E29 的“可以使用”与实际效果遮罩分开；许可不是 actual performed，
  不能据此解锁 then。古兹马 FAQ 的允许使用且后段不执行正是此边界。
- **具体未决：** 同一实际来源效果被 `CN.E29` 与 `ordinary` 同时保护同一 subject，
  且没有其他合格 target／独立 binding／已知可行付款证明可用时，
  返回 `needsRuling`；不默认“有一个 E29 就允许”，也不默认“有 ordinary 就否决”。
  另有明确资格证明可以先证明整体可用，不必解出无关的未知 leaf；这只是证明顺序，
  不改真实执行顺序或 then 依赖。“已知付款证明”指付款后的使用资格，非付款本身算变化。
  重叠下实际 effect 被挡并无争议，未决的是使用许可；来源充分的单 E29 仍允许
  card use 后 actual performed=false、then 不解锁。该未决不拖住其他已明确子集。

- 四类 native 的候选范围、实际受作用者、来源保护、无变化使用门槛应分层；
  尤其 switch 区分 C04／C05，Trainer 保留 EX 的专门许可。
- 多 binding 的完整可用性、同一付款前后的一致性与真实 then 依赖由宿主负责；
  不能用单个叶子的 canUse 证明整棵程序正确。
- 不新增条件 handler，不把“同状态＝无变化”推广至 condition／lasting 或其他操作。
- 本次完成原件哈希／页数核验、指定条款及上述补读的证据审查；
  **未运行 full test 或定向测试，未修改任何其他文件或 Git。**
