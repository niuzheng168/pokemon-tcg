# Stage27：现场选择卡面招式的禁用匹配边界

**2026-10-20 primary sidecar。仅新增本文件，不修改其他文档、代码、schema、
生成器或 Git；未运行测试。** 本轮目标仍是父线完成实际选择执行链，
不是以本文或纯候选查询代替 C15 的实现验收。所有场景为 synthetic，不审批真实整卡。

## 1. 优先结论

**固定原文不能单独确定：“禁用被选择的招式”是否扩及其他来源直接提供的同名招式。**
它既没有规定软件 `attackId`／物理 ref 是唯一官方匹配标准，
也没有给出“所有同名授予／复制路线一律禁止”的统一规则。

- **选择范围确定**：只选对手战斗宝可梦当前卡面所拥有的招式；额外获准使用的不算拥有。
- **无歧义命中确定**：所选卡面招式本体受到禁用，其他不同名招式不因此被锁。
- **复制有明确边界**：C18 p40 说明复制的是内容，实际使用仍是外层招式。
  不能拿复制内容的名字代替实际宣告招式名做禁用匹配。
- **不同静态身份的同名直接使用来源**：真正遇到此竞争时才 `needsRuling`；
  不因目标有 extra／grant／copy 就拒绝创建锁或禁掉全部额外招式。
- **真实继承不因换顶层清锁**：D19 p52 明确转移附加效果。沿真实继承历史保留原
  ref；不同物理实例解析到完全相同获审 `definitionId + attackId` 时，本轮按相同
  静态打印身份处理。这是限定软件等价，不是把不同定义的同名招式全部归一。

因此 `restriction.attackNames` 可以表达经来源审核的**明确点名禁用**，
也可以保存现场选择的名称锚；但**选中锁只存名称、随后无条件禁止一切同名 route，
不构成这些页已经证明的语义**。反过来，只用未限定来源的 `attackId` 也会误判碰撞。
父线本轮采用下面的独立选中锁协议，不以扩张通用名称禁用来代替这一区分。

## 3. 最小不误判的匹配方案

**父线采用的接线合同（软件表示，非本工作者实现验收）：**

```js
{ op: 'ownedAttackRestriction', scope: 'all',
  reference: { instanceId: selectedTopCardId, attackId: selectedAttackId } }
```

其 ongoing 记录必须另有固定的受影响 `targetId`；`scope:'all'` 不表示全场 Pokémon
共同受锁。`reference.instanceId` 指被选目标的卡面物理实例，不是施招者或 grant
使用者的实例。两个字段的 ref 要求该获审卡面内部 attackId 唯一；
卡内 ID 无法消歧属于目录／协议问题，不能以同名跨来源未决掩盖。

为现场选中锁保留两层事实：

1. **选择锚**：受影响 `pokemonId`、当时实际顶层 `card instanceId`、
   获审定义／卡内招式条目标识、原 `attackId`、原 `attack.name`。
   名称可以从固定获审定义读取并核验，不要求把它另变成禁用所有同名路线的规则。
2. **实际宣告 route**：本次使用的 Pokémon、原生／道具／grant 的来源 ref、
   真实宣告的招式及名称；复制内容的 ref 单独保存，不覆盖外层宣告身份。

**实际 grant route 必须解析：** 当前使用者的 `instanceId` 可能仍是其顶层卡，
不能据此把 grant 当原生。直接 grant 宣告需取其实际打印内容来源 ref，
而复制的内部执行不能反过来覆盖外层宣告记录。若直接路线确实解析到所选同一
物理打印 ref，仍是已选本体，不能换一个许可 route 绕锁；若是另一物理实例但
解析到完全相同的固定获审 `definitionId + attackId`，本轮亦按同一静态打印身份
匹配。其余再按下表区分不同名与真正同名竞争。不能只比较执行者
`instanceId + attackId`，也不能只因物理 ref 不同便制造规则未决。

这只是软件协议建议，字段名称可精简。关键是能证明“选了哪一个打印条目”
和“现在究竟使用哪一个招式”，而不是让玩家用名称或 ID 自报匹配结果。
名称来自固定获审定义；不静默作跨语言、同音、去空格或其他未获审别名归并。

在该锁对这只 Pokémon 的当前期限有效、且尚未被清除的前提下：

| 本次实际使用路线 | 对这个现场选中锁的结论 |
| --- | --- |
| 所选卡面条目本体；原生或直接 grant route 明确解析到同一物理打印 ref | 在所采用的最小身份协议中禁止；能量足够或换许可 route 不改变本体命中 |
| 实际直接使用来源为另一物理实例，但获审 `definitionId + attackId` 完全相同 | 本轮按同一静态打印身份禁止；这是限定软件等价，不以名称相同替代定义一致 |
| 另一卡面条目，且名称不同 | 不受此锁禁止；仍检查其他独立规则 |
| 道具／grant 提供不同名招式，即便 `attackId` 恰好与所选相同 | 不因 ID 碰撞而禁止；其实际额外使用许可仍须合法 |
| 实际宣告不同名招式 B，B 内部复制所选招式 A 的内容 | 不因复制内容 A 而封锁 B；使用身份按 C18 判断，不在复制入口重新当成宣告 A |
| 不同获审定义／不同静态条目的卡面／道具／grant，实际直接宣告同名 A | **needsRuling**：这些页不足以确定现场选中锁是否覆盖该同名 route；仅物理 ref 不同但静态身份相同不属于本行 |
| 真实 `effects.inherit` 将附加效果转到新顶层卡，锁仍在期限内 | 保留原选择 ref 和锁；再以实际声明路线匹配，不因 `targetTop` 改变清锁或拒绝 |
| 锁已过期、目标已回备战／离场／进退化而清除 | 不受这个已清除锁约束；不能只因卡名／ID 重现恢复旧锁 |

**把未决限制到真正竞争：** 应在有效锁与实际待宣告 route 发生上述同名竞争、
且此问题确实影响该行动可用性时报告局部 `needsRuling`。若原生所选招式已明确禁止，
无须再扫描全目录制造未决；不同名且合法的额外路线也不应一起被阻塞。
不要因目录存在一个同名 grant 就拒绝本次选锁，更不能把未知悄悄当 false 或 true。
候选展示／命令门禁应保留这种区别，不能以“隐藏全部 extra”伪装已经解决。

父线采用固定 reference＋实际 grant route 匹配；名称用于区分碰撞和识别尚未解决的
同名竞争，**不自行签发同名跨来源裁定**。明确点名的旧锁与独立
`ownedAttackRestriction` 不必因此强制合并成同一种匹配模式。
本合同不是对全同名规范的完整解决声明。

**继承补充边界（D19 p52–53）：** C15 的正常回备战／离场／进退化清除，
不能机械套成“被选物理卡一离开顶层就清除”。D19 的继承是明确转移附加效果的
操作，示例甚至把旧卡送入弃牌区或手牌；这里应依已获审继承效果保留限制，
而非把旧卡去向误当成受影响主体正常离场。该推导没有将继承认作进化。
软件须依据真实执行的 `effects.inherit` 的 `from → to` 历史链证明转移，
保留原选中 ref；任意修改顶层、伪造历史或新的同名主体都不能自行继承锁。

不同物理实例的同一固定获审 `definitionId + attackId`，只在确为同一静态条目、
定义及名称锚一致时作软件身份等价；定义键不能可编辑地指向另一份招式内容。
本轮核读未见与此限定表示明显相反的条款，但 D19 的特性 FAQ 也不能冒充
“所有同名招式等价”的专门裁定。不同定义的同名招式仍仅在实际竞争时未决，
不增加跨卡名、跨语言或仅凭名称的归一化；继承不会改变 C18 的外层宣告边界。

## 4. 本轮必须真正接通的选择执行链

1. **建立候选**：按获审封口式指令找到对手当前战斗 Pokémon；
   仅枚举其当前顶层卡面招式。不能用包含道具／grant 的整个 `attacksFor` 当拥有池，
   也不因能量不足、已有禁用而删掉仍印在卡面的招式。
2. **显式选择**：有候选选恰好1个；合法空池不虚构招式、不写全招式锁，
   其他说明文依 II.A 继续。只有额外招式而没有卡面招式，仍是拥有池为空，
   不是“有 extra 所以整张卡不支持”。缺定义、伪 ID 不当成空池。
3. **暂停与回答锚定**：回答需对应原请求、实际目标／顶层卡、候选列表、
   选择者及原程序位置；名称、ID 或整个候选回执一起被篡改也不能自证有效。
   错目标、错顶层或非候选回答应协议拒绝，不包装成新的规则未决。
   这是现场选择时的锚定；已合法附锁后发生有证据的继承，不因新顶层与原锚不同
   而倒推原选择无效。
4. **保护与执行分离**：卡面候选事实不因保护消失；C17 p38 明确该禁用会被
   相应招式效果保护阻止。选择本身不等于成功附锁，不能伪造 performed。
   本文不声称原文规定了全保护时必须怎样弹 UI；软件暂停顺序不是新官方规则。
5. **附加真实限制**：成功时把所选身份绑定到受影响 Pokémon 的限时效果，
   不删改 `CardDefinition.mechanics.attacks`。按下一个对手回合生效，不含检查；
   使用 C15 明确的回备战／离场／进退化清除，不让无继承依据的同名新实例承接旧锁；
   已获审继承按 D19 转移附加效果，不仅因顶层物理实例改变清除。
   新 `ownedAttackRestriction` 只允许由已验证现场选择链生成；拒绝 continuous
   生产者、普通 timed AST 或未绑定选择的 payload 直接签发。允许恢复真实已生成的
   ongoing 记录，但仍须核对原选择／程序锚点，不能只凭 op／ref 字段自证合法。
6. **限制参与真实宣告**：实际 `legalActions`／命令验证使用同一匹配语义，
   同时保存原生／授予 route；不能 UI 显示禁用但换 `referenceId` 就绕过原生所选条目，
   也不能为防绕过把所有其他来源 ID 相同的招式误封。
7. **恢复沿用同一事实**：恢复不重新选择、不扩展名字集合、不把额外来源变成原生；
   程序／选择／持续记录仍受宿主获审来源和执行身份约束。经继承的记录保留原 ref，
   核验真实 `from → to` 链；新顶层可以是不同定义，仍保留附加效果。只有匹配本次
   直接使用是否为同一静态招式时才比较固定获审定义，不要求当前顶层等于原卡或原定义。

这条链能先完整交付普通无同名竞争的 C15 功能；特定同名 route 的局部未决
不应拖住已确定的选择、施加、期限、清除和恢复。

## 5. 最低 synthetic 验收清单

- 目标原生 A／B 加额外 G：候选只有 A／B；选 A 后有效期内 A 被禁、B 可用。
- 只有额外招式、原生空池：无锁，其他独立内容正常；不是整体拒绝额外机制。
- 道具／grant 与 A 使用同一个局部 ID 但不同名：无误封；不同静态身份的真正同名
  直接使用 route 才局部未决，其他已知可行行动保持可行，未决不得消耗资源／RNG／次数。
- grant 的执行者顶层实例与原生相同、但实际打印来源不同：不得错当原生；
  直接 route 真正解析回所选同一 ref 时也不能靠切换 route 绕锁。
- 宣告 B 再复制 A：不能按复制内容名封锁 B；复现 C18 p40 的实际使用身份边界。
- 来源保护挡住附锁；已附锁后才恢复保护不取消它；选择不能充当已执行。
- 期限及回备战／离场／进退化清除；再次入场、同名／同 ID 重现不复活旧锁。
- 真实继承的 `from → to` 链保留原 ref 和有效锁；换成另一物理实例的相同获审
  `definitionId + attackId`，实际直接使用仍命中。普通进退化仍清除，不混作继承。
- 继承到不同定义后，实际直接使用不同名招式不受旧锁；不同定义同名才局部未决；
  复制内容仍不替代实际外层宣告。
- 选择前后保存恢复；无合法过渡证据地换目标、顶层、条目、名称、来源或程序位置
  均拒绝；真实继承历史不能被当成顶层篡改，也不能凭伪历史恢复已清除锁。
- continuous／timed AST 直接制造选中锁、删掉 ongoing.targetId 或伪造选择锚点均拒绝。
