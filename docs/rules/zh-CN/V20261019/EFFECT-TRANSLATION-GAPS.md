# 效果翻译与缺口初步统计（2026-10-22）

这是**机器候选与模型理由的诊断报告**，不是新的规则裁定或卡牌准入。下文的 §5 编号来自给翻译模型的
`handler-reference.md`，**不是简中官方规则的条款号**；真正补规则仍须独立查阅官方依据、实现并测试。
`unsupported` 也可能是构造器或参考文档过窄，不能直接当作内核缺失。

### 首批接入（2026-10-22）

已建立独立于模型答案的完整卡文模板：抽牌、反伤、回复、异常状态、硬币状态／伤害公式、
下回合防御／招式／撤退限制、互换、简单检索、明确的发动型特性和双重无色能量。
只在完整文本匹配且两个原结果与独立构造的程序逐字段相等时认证，当前 **423 个单元／18 个模式族**。
局部效果键、硬币变量可作等价重命名，但不能忽略 usage、选择器、条件、顺序或丢失的其他条款。

补查原字段审核未比较的 `rule_text`：新机器定义须通过两个完整卡图读数的规则框门禁；
不能用库中很稀疏的太晶标签推断「没有规则」。发现班基拉斯V一份读数的「□□」后，
只读本机卡图核对 V 规则，修正绑定原图及两个读数的摘要，仍标机器层，不把整卡升级人工审核。

### 已审核程序复用及共享模式扩展（2026-10-22）

## 6. 下一阶段的能力审计（不是已经完成的实现）

1. **先区分构造器与内核**：现有卡 schema／引擎已包含攻击失败检查、GX／VSTAR 权利、特性费用、
   绑定触发／费用和特殊能量附着约束；t1 参考明确写着构造器不能传入这些字段。
   应逐合同核对构造器、来源权限、准入和恢复，再更新参考，不直接把 `unsupported` 当作内核缺失。
2. **组合语义是高覆盖缺口**：效果执行器已有 sequence／then／optional／coin／orElse，
   但现有控制 handler 只允许很小的静态叶集合。扩展时必须保留原有费用、目标、阶段和私有日志证明。
   不能在打开整个程序时提前求值 draw-until 等依赖前一步结果的读数，也不能借包装器绕过攻击专用／主体局部限制。
3. **版本化补译**：只有完成新接口及语义测试后，才对实际需要的新能力使用新的参考摘要／缓存版本做增量补译；
   保留本轮全部 t1 缓存，不覆盖旧结果，不重新付费翻译已有可用条目。
4. **全池而非方便子集**：费用、条件式非伤害、持续时间、对手区域、特殊能量和特殊阶段仍须逐项补齐；
   继续处理排除清单，不把当前可用卡数或全绿测试当作 13,706 目标完成。

## 5. 复现与边界

完整数据在本机 `.data/effect-translation/`，不进 Git；重建需要卡牌库索引、最终卡文核对和模型缓存。
先通过 `FOUNDRY_ASTRA_ENV`／`FOUNDRY_SOL_ENV` 指向仓库外的密钥文件，禁止打印或提交密钥。

```sh
node scripts/effect-corpus.mjs                 # 或 --out <文件> 先检查变化
python3 scripts/effect_translate.py status
python3 scripts/effect_translate.py translate --model astra --workers 2
python3 scripts/effect_translate.py translate --model sol --workers 2
python3 scripts/effect_translate.py check
python3 scripts/effect_translate.py score
npm run cn:effect:gaps                        # .data/effect-translation/gap-report.json
```

增量翻译会跳过已有 UID；旧 UID 结果保留，不删除。缺口工具拒绝语料和检查结果 UID 集合不一致的旧统计。
无需本机数据或密钥的纯回归：`npm run test:effect-corpus`（7 项，已纳入 `npm test`）。
