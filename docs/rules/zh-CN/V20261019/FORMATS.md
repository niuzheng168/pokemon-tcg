# CN / V20261019 卡池快照（开发中）

卡池准入、规则实现、卡牌内容审批、赛事管理是不同层次。
**本页不表示所有可用卡已经实现或已获生产审批，网站仍使用旧教学引擎。**

## 1. 来源与日期

本轮直接下载并逐项阅读简中官网原始 HTML：

- `https://www.pokemon.cn/tcg-rules-regulation`，页面更新／生效日期 2026-09-16。
- `https://www.pokemon.cn/tcg/other/17158.html`，2024-05-19 的历史调整通知，
  明确自 **2024-06-18** 起标准赛制排除基本妖能量；不是 6 月 1 日。
- `https://www.pokemon.cn/tcg-rules-regulation-extra/`，主赛制页链接的特殊卡牌说明。

这三份网页的**实际取得日期是 2026-10-20**，不回填成 10 月 19 日。
配置仍是本项目的 `V20261019` 快照，使用页面声明在 10 月 19 日已经生效的范围，
不声称在 19 日已取得这些原字节，也不声称有官网历史存档证明页面未修改。
规则登记保存原始字节 SHA-256、大小和核对方法，不使用搜索摘要中的卡名名单。

网页模板包含动态标记，日后下载的完整 HTML 可能不同。
来源检查只接受已核对的原字节；`--download` 不能用新字节自行刷新旧哈希。
无法重新取得相同字节时须取得可信原缓存，或重新审查新快照，
不能把失败当作“规则一定变了”或绕过校验。
PDF 和 HTML 原文都只在忽略提交的来源缓存中，不加入 MIT 分发包。
第二十二轮另固定三个登记的基础玩法页面，现登记八份来源均有原字节指纹；
实际取得日同为2026-10-20，无版本基础页没有19日的历史字节等同性证明。
保留 `pageName` 查询来区分对战方式和特殊状态，不能用共用canonical合并。
其他未登记网页和卡牌仍须各自核验，不由这八份来源自动获准。

## 2. 四种身份分别保存

```js
ruleset: { region: 'CN', version: 'V20261019' }
format:  { region: 'CN', version: 'V20261019', id: 'standard' } // 或 open
matchMode: 'normal' // 或开发中的 tiebreak
printing: { language: 'zh-Hans', series: 'scarlet-violet', /* ... */ }
```

没有 `latest`、语言推断或未带版本的 `'standard'` 别名。
`open` 是简中官方“开放赛制”，不是把国际 Expanded 的卡池／禁牌移植进来。
`getFormat`／`listFormats` 返回固定只读配置；`validateFormatDeck` 同时执行
60 张、基础宝可梦、同名／组别限额和所选卡池检查。

`casual60`／`tiebreak60` 仅保留为低层开发兼容入口，**不是官方卡池**。
选择抢分赛的奖赏模式不会取消所选标准／开放卡池。
当前一奖赏模式仍有“已获奖赏张数”作用域等未验收项，不能称为完整赛事实施。

## 3. 固定卡池政策

| 范围 | 标准 | 开放 |
| --- | --- | --- |
| 普通卡 | 标记 G / H / I / J | 太阳&月亮、剑&盾、朱&紫三个已审核系列 |
| 基本能量 | 草、火、水、雷、超、斗、恶、钢 | 上述八种及妖 |
| 30 周年商品例外 | 按标准标记规则，不套用开放例外 | `30thC` 须有标记；`30thDC` 不要求标记；`PROMO` 且完整卡号 `XXX/30th-P` |
| 旧系列指定同名卡 | 26 个指定训练家名称，执行最新版说明文 | 32 个指定训练家名称，执行最新版说明文 |
| 指定禁牌 | 不套用开放名单 | 玛夏多且印刷特性为破罐破摔、阿塞萝拉、全满药 |

八／九种基本能量是独立例外，不依据它们的标记判断。
基本妖能量即使带有 G 标记也不能借此进入标准卡池。
禁牌核对不可使用战斗时被消除后的特性视图，也不把所有玛夏多一概禁用。
同卡不同图案、稀有度或标记不能绕过开放禁牌。

标准与开放各有自己的旧卡最新版名单，完整数据保存在
`public/rules/zh-CN/formats/V20261019.js`。例如“离洞绳”在开放名单中，
不在标准名单中；“博士的研究”“老大的指令”的人物／插画差别不是不同卡名。
不能将展示用的括号人物名当成不同的同名限额键。

## 4. 印刷与最新版绑定审查

新增的印刷资料仍属于静态元数据，不进入战斗状态：

- `series`：经独立审核的系列分类，不猜测商品编号前缀。
- `releasedOn`：该实体印刷的首发日期，不是导入日期或同名卡首次出现日期。
  官方卡池入口需要真实有效、且不晚于快照日的日期。
  缺少审核或晚于快照属于**该快照未获准入**，不冒称官方永久禁止。
- `formatReviews[]`：指定旧卡的逐赛制最新版等价性审查；
  包含明确赛制版本、`latestPrintingId` 与卡牌／勘误证据。

旧卡能否使用不是只看名字：

1. 独立审批覆盖这张旧印刷及其定义绑定。
2. 对应官方旧卡名单包含该规范卡名。
3. 旧系列卡明确绑定本快照下最新版的执行定义。
4. 唯一对应的 `formatReviews` 给出经审查的最新印刷和卡牌／勘误依据。
5. 最新印刷在已审批目录中（不要求加入卡组），绑定**同一执行定义**，
   并在相应卡池中可用、已于快照日期发行。

标准重印的最新锚点必须符合当前标记范围；
开放中明确的审查也可以确认某张旧印刷文字至今未变。
同名但效果不同的两份定义不能由名字查询自动合并。
一般游戏规则来源不能代替某张卡的最新版说明文证据。

以上字段全部参加印刷规范审批、发布包封签和 catalog 身份。
从下载数据中自行填写这些字段或重算哈希不能签发审批。

## 5. 对局、恢复和可见视图

创建对局时检查两副卡组。恢复时重新检查每位持有者全部原始物理卡，
包括当前在弃牌区、放逐区、场上或其他区域的卡，不能只检查剩余牌库。
原来的卡牌守恒、定义绑定、版本、catalog 与 continuation 检查仍保留。

私有协议升级为 `CN-game-dev-13`；不静默接受旧版缺少卡池／奖赏模式的存档。
双方玩家投影包含只读 `format`、`matchMode` 和规则来源 trace，
不暴露牌库、奖赏的内部身份，也不让客户端自行填写来源改变准入。

发布入口需要独立审核的发布包和明确的版本化卡池；
开发兼容卡池只可经低层开发 API 使用，不能冒充正式发布对局。
即便卡池与发布审批都通过，未实现的特殊卡规则仍须由执行门禁拒绝，
而不是因为系列在开放卡池中就默认支持它的全部行为。
