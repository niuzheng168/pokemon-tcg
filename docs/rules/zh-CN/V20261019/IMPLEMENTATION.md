## 目标与边界

- 地区为中国大陆 `CN`，卡牌发行语言为 `zh-Hans`，规则快照版本为
  `V20261019`。这三个概念与界面语言、卡池赛制、官方文档版本分开保存。
- 官方简中规则和适用的官方卡牌说明优先于 Academy、国际版、
  52Poké 以及现有测试的行为。不可无声导入国际版裁定。
- 逐条规则保存 source of truth，包括官方文档身份、章节、PDF 页序、
  读取日期、可取得时的内容哈希；实现与测试使用稳定的规则 ID。
- 卡牌印刷身份、规则定义、可执行效果和对战中的实例分离。原始 metadata
  保留不变；来源不充分、规则不明确和未实现的效果不得伪装为已支持。
- 数字模拟器不能证明实体卡真伪、组织线下赛事或替代主裁判。
  必须显式区分对战内核、赛制合法性和赛事管理约束。

## 第三轮：有依赖的效果、保护和持续时限

- 新增递归、严格验证的效果指令与可序列化执行帧：
  `sequence`、`then` 和整个后续效果的 `optional`。
  “然后”取决于前文至少部分实际执行；选择目标不算执行成功，
  也不把前文不足但部分执行误判为全部失败。
- 在进入执行前验证整个程序，包括最终不会执行的分支；拒绝未声明的
  指令、未知参数和语义 hook 中会被忽略的游戏动作。
- 区分招式伤害保护与效果保护。受保护目标仍可被选择，
  “选择备战宝可梦并互换”与“使战斗宝可梦互换”检查不同受影响对象；
  覆盖官方“古兹马／离洞绳”说明的四种位置组合。
- 指示物转放独立于伤害；目的宝可梦有保护时，不退还已从来源移除的
  指示物。已存在的特殊状态不会因为后来的保护而被清除。
- 接通有效弱点／抗性、伤害修正和保护；无视防守方附加效果
  不恢复被移除的弱点，也不自动获得无视非伤害效果保护的权限。
- 引入带来源、目标、清除策略及精确边界的持续效果账本。

  “直到下一个自己／对手的回合结束前”从当前持续到对应检查结束。

## 第四轮：即时触发、受伤反应和昏厥连锁

- 新增严格的 `trigger.schema.json` 与 `triggers.js`。触发事件、受影响主体、
  可选执行的控制者、来源区域、回合／结束玩家、战斗位置、属性／规则框、
  致因和执行作用域分别建模，不从自由文字猜测。
- 接通七类窗口：招式伤害、昏厥、从手牌放于备战区、从手牌进化、
  能量附着、回合结束和宝可梦检查。准备阶段的放置不冒充从手牌使出；
  特性不能等下一项操作后再补用。
- 受伤反应在招式的其他效果后、昏厥检查前执行。零伤害、受到伤害保护、
  纯指示物效果不误触发受伤反应；即使攻击者已换到备战区，反应仍使用
  事件中原攻击者身份，而不是临时取当前战斗宝可梦。
- 记录引起致死状态的原因；攻击伤害昏厥与效果指示物昏厥不混算。
  昏厥批次一旦确认就锁定，在所有同时触发效果及新昏厥连锁处理完前，
  不提前弃置源宝可梦或其附着卡。移除连续 HP 来源产生的新昏厥继续处理，
  双方奖赏处理完才判断胜负。
- 排序玩家是受影响宝可梦的持有者，不一律采用当前回合玩家。
  可选发动的控制者另行保存；拒绝发动不消费次数，接受后才登记
  明确的单只／共享次数。一个特性的多个后续效果保留说明文顺序。
- 检查效果逐项选择整个状态组之前或之后，再由对应持有者决定次序；
  不能插入中毒、灼伤、睡眠、麻痹的状态组内部。依赖当前特殊状态的
  条件在选定位置重新确认，覆盖先睡眠恢复、后效果不再适用的情况。
- 新增手牌基本能量的效果附着。来自手牌的触发按实际卡牌逐张执行，
  双重能量的一张不当成两次；从弃牌区附着不误触发手牌限定效果。
  能量卡自身的“这张卡被附着”可与同一宝可梦上的其他能量区分。
- 玩家选择界面获得公开的触发来源、能力和受影响目标身份；
  不直接发送内部绑定、参数、执行帧或整张私有棋盘。
  触发记录恢复时校验卡牌持有者、已批准绑定、控制者、次数和致因。
- 局部效果只得到自身目标的只读上下文，且指令不得写入其他目标；
  两个持有者的这种独立效果可技术串行化。**跨持有者、存在全局依赖的
  同时效果目前仍明确报需简中排序裁定，不能视为已完成支持。**
- 开发存档协议升级为 `CN-game-dev-3`。当前 **162 项**规范测试通过，
  新代码覆盖率：行／函数 **100%**、分支 **96.47%**；未降低门禁。
  `npm test`、旧引擎 15,130 场卡组组合对局、网页构建和 diff 检查通过。
- 尚未接通招式施加的延后反应载荷、离场后完整最后已知信息、
  加入手牌前窗口和相关复杂操作；也未切换网站入口或提交／推送。

## 第五轮：基础／对战／派生属性、附加伤害与封锁

- 按用户补充要求明确三层属性。不可变定义中的 `mechanics.hp` 是卡面基础
  最大 HP；运行时只保存伤害指示物、特殊状态、附着卡、次数、事件事实和
  有来源／目标／时限的效果。玩家视图分别计算 `effective.maxHp` 与
  `effective.currentHp`，不在卡面或存档中维护第二份可变剩余 HP。
- 收紧 `facts` 为具体事件字段，拒绝将卡面属性或派生 HP 塞入任意键值包。
  测试覆盖同定义不同实例隔离、增 HP 道具的装卸、回复、进化继承伤害、
  剩余 HP 的零下限及无效混层字段。进化和道具不会修改原始已审批定义。
- 接通额外备战／自身／指定数量目标的招式伤害，与放置指示物效果分离。
  主目标和同阶段多目标使用放置伤害前的修正模型，防止早结算的伤害
  改变后一目标的连续保护；说明文阶段的伤害再以当时场面计算。
  按目标独立检查备战弱抗、伤害保护、增减伤适用方与位置及忽略选项。
- 私有存档保存可恢复的宣告招式帧、伤害模型和实际受伤事件，
  玩家视图不暴露该内部工作帧。多目标选择测试覆盖简中 exact／upTo／all、
  数量不足、无效回答原子拒绝和每个选择点的 JSON 恢复。
- 增加宝可梦招式／撤退封锁，包括指定招式身份、明确时限、
  回备战／进化的清除策略，以及禁止优先于许可。
  交换效果不冒充撤退，招式封锁也不误当作特性不能发动。
- 玩家训练家卡封锁独立存储于 `playerOngoing`，区分物品、支援者、
  道具、竞技场使出及竞技场发动。宝可梦效果免疫不阻止玩家封锁；
  有时限玩家封锁不跟随原宝可梦的回备战、进化或离场自动清除。
  连续封锁仍根据来源和战斗位置实时判断。
- 接通已施加的延后反应：保留固定目标、原始卡牌来源、将来触发条件、
  已审核指令和到期边界。反应后续沿用事件中的攻击者与来源类别，
  在其他招式效果后、昏厥前执行；反击指示物仍可被适用的效果免疫阻止。
  新建立的反应不能回溯触发此前已记录的伤害；对外不泄露内部指令程序。
- 延后指令的执行权限与原 handler 分开声明，并校验未执行分支。
  仍未完成任意延后昏厥、所有最后已知信息、嵌套延后反应等完整机制；

  当前 **185 项**规范测试通过；手写规则代码覆盖率行／函数 **100%**，

## 第六轮：来源消除与原始 PDF 冻结

- 新增有来源的 `suppression` 描述和独立依赖求值器。单个特性、附着道具、
  竞技场、内建规则、已建立的时限效果分开建节点；特性／道具消除不修改
  基础定义、不丢弃卡牌、不撤回已建立效果，也不重置使用次数。
- 按简中 D-13 的例子接通基本宝可梦、规则框、属性／标签、持有方、
  目标／来源战斗位置及明确例外。有效特性计数可经 handler 只读上下文参与
  伤害公式，不误数已被消除的卡面特性。真实特性必须位于
  `mechanics.abilities`，不能借内建规则绑定逃避消除。
- 来源可用性接通主动特性、连续属性／伤害／封锁、原生受伤／昏厥等触发、
  赋予的道具招式和玩家投影；道具失效仍占用附着位，原卡牌的招式仍存在。
